# 概念 07｜2-3 树与红黑树（Red-Black Tree）

> **一句话人话定义**：为了不再像[普通二叉树](./06-二叉搜索树与跷跷板旋转.md)那样往底下乱挂长歪，**2-3 树**允许一个盒子里并排住 2 个数，满 3 个数就把中间那个数往上顶（自底向上造山，天生绝对水平对齐）；而 **红黑树** 就是用普通二叉树节点 + **“红色胶水（把同盒室友涂成红色粘在黑节点身上）”** 演的一出皮影戏，100% 复刻了 2-3 树！

## 1. 它被什么痛点逼出来的？

在 [概念 06](./06-二叉搜索树与跷跷板旋转.md) 里：
- **普通二叉搜索树（BST）** 遇到递增数据 `10, 20, 30, 40` 会歪成单向链表；
- **AVL 树** 虽然靠旋转保住了平衡，但因为要求“左右高度差绝不超过 1”，每次插入数据都要频繁旋转，写代价太高。

怎么才能**既保证树绝对不会歪成链表，又在插入数据时尽量少旋转**？

## 2. 从 0 到 1 生长慢放：先看 2-3 树，再同屏破译红黑树

### 2.1 第一步：看懂 2-3 树的“横向挤盒子、满 3 向上造山”
2-3 树定下规矩：新来的数字**绝不往下新建一层**，而是先挤进底部的现有盒子里（一个盒子最多允许住 2 个数）；**只有当盒子里塞满 3 个数撑爆时，才把正中间那个数向上弹射一层！**

看依次插入 `10 -> 20 -> 30 -> 40 -> 50` 的全过程：

```text
① 插 10、插 20（直接横向挤进同一个盒子，树高只有 1 层！）：
   [ 10 | 20 ]

② 插 30（变成 [10 | 20 | 30] 满 3 撑爆！正中间的 20 向上弹射当父母，10 和 30 裂成左右孩子）：
         [ 20 ]
        /           [ 10 ]   [ 30 ]

③ 插 40（去右边找 [30]，还没满，横向合体）：
         [ 20 ]
        /           [ 10 ]   [ 30 | 40 ]

④ 插 50（右边变成 [30 | 40 | 50] 满 3 撑爆！中间的 40 向上弹射，直接融进头顶 [20] 的盒子里！）：
         [ 20  |  40 ]         <-- 头顶 2 个路标，分出左(<20)、中(20~40)、右(>40)三条路
        /      |           [ 10 ]  [ 30 ]  [ 50 ]    <-- 所有底部的叶子，100% 站在同一条水平线上！
```

### 2.2 第二步：用“红胶水室友”一句话破译红黑树 5 条规则
2-3 树虽然完美，但代码里一会儿一个节点存 1 个数、一会儿存 2 个数，不好写。
于是 **红黑树** 决定：**继续用每个节点只存 1 个数的普通二叉树；但如果两个数在 2-3 树里住在同一个双数盒子里（比如 `[ 30 | 40 ]`），就把小弟 `30` 涂成红色，代表它用一根“红色胶水”粘在大哥 `40(黑)` 身上！**

```text
2-3 树里的双数盒子：                红黑树里的等价画法：
  ┌───────────┐                            40 (黑：代表这一层的盒子本尊)
  │ 30  |  40 │        ========>          /  (红胶水：代表他俩其实住在同一层同一个盒子里)
  └───────────┘                        30 (红：粘在 40 身上的同盒室友)
```

对照这个物理图像，教科书里那 **5 条天书般的红黑规则** 瞬间变成大白话：
1. **节点非红即黑**：黑的是独立盒子本尊，红的是粘在黑节点身上的同盒室友。
2. **根节点必为黑**：根节点头顶没人，没法当别人的红室友。
3. **空叶子（NIL）为黑**：统一边界的哨兵。
4. **不能有两个连续红节点**：一个盒子最多住 2 个人（1 黑 + 1 红）。连着两个红说明盒子里塞了 3 个人，撑爆了必须分裂！
5. **从根到任意空叶子，路过的黑节点数完全相同**：因为 **1 个黑节点 = 2-3 树里的 1 层盒子**！既然 2-3 树所有叶子天生水平对齐，忽略掉红室友，走哪条路数出来的黑盒子层数当然 100% 相等！这也直接保证了**最长的路（黑红相间）绝对不会超过最短的路（全黑）的 2 倍**！

### 2.3 第三步：红黑树插入 `10 -> 20 -> 30 -> 40 -> 50` 逐帧慢放
新节点一律先涂成**红色**（代表先往别人盒子里挤），靠三个固定动作维护秩序：
- **动作 A（右红左旋）**：红室友如果挂在右边，左旋一下让红室友统一站左边；
- **动作 B（连红右旋）**：左边连续两个红室友，右旋一下变成“黑父牵左右双红”；
- **动作 C（双红变色 = 满 3 分裂上推）**：一旦黑节点**左右两边同时挂着两个红孩子**（左红 + 自己黑 + 右红 = 满 3 个数撑爆！），立刻把**两个红孩子变黑**（独立成两个新盒子），**中间父亲变红向上弹射**（若已是树根则保持黑）。

```text
【第 1 步：插 10、插 20】
  10(黑) 右挂 20(红) ──(动作A:左旋)──►    20(黑)          （对应 2-3 树 [10 | 20]）
                                          /
                                       10(红)

【第 2 步：插 30（凑成左 10红 + 根 20黑 + 右 30红，满 3 分裂变色！）】
       20(黑)                              20(黑)          （对应 2-3 树 [20] 裂出 [10] 和 [30]）
      /      \       ──(动作C:变色分裂)──► /         10(红)   30(红)                      10(黑)   30(黑)

【第 3 步：插 40（挂在 30 右边，动作A左旋）】
       20(黑)                              20(黑)          （对应 2-3 树右侧变成 [30 | 40]）
      /      \       ──(动作A:对30左旋)──► /         10(黑)   30(黑)                      10(黑)   40(黑)
               \                                 /
               40(红)                         30(红)

【第 4 步：插 50（右侧凑成 30红 + 40黑 + 50红，再次满 3 分裂把 40 推上根！）】
       20(黑)                20(黑)                  40(黑)  （对应 2-3 树根 [20 | 40]，底 [10],[30],[50]）
      /      \              /      \                /         10(黑)   40(黑)  ──(C)─► 10(黑) 40(红) ──(A)─► 20(红)   50(黑)
           /      \               /     \        /              30(红)   50(红)        30(黑)  50(黑)  10(黑)   30(黑)
```

## 3. 30 行极简代码原型：手写左倾红黑树（LLRB）插入与自动平衡

```js
const RED = true, BLACK = false
const isRed = n => Boolean(n && n.color === RED)

function rotateLeft(h) {
  const x = h.right; h.right = x.left; x.left = h
  x.color = h.color; h.color = RED; return x
}
function rotateRight(h) {
  const x = h.left; h.left = x.right; x.right = h
  x.color = h.color; h.color = RED; return x
}
function flipColors(h) { // 动作C：满 3 分裂变色上推
  h.color = RED; h.left.color = BLACK; h.right.color = BLACK
}

function insert(h, val) {
  if (!h) return { val, left: null, right: null, color: RED }
  if (val < h.val) h.left = insert(h.left, val)
  else if (val > h.val) h.right = insert(h.right, val)
  if (isRed(h.right) && !isRed(h.left)) h = rotateLeft(h)     // 动作A：右红左旋
  if (isRed(h.left) && isRed(h.left.left)) h = rotateRight(h) // 动作B：连红右旋
  if (isRed(h.left) && isRed(h.right)) flipColors(h)          // 动作C：双红分裂
  return h
}

let root = null
for (const v of [10, 20, 30, 40, 50]) { root = insert(root, v); root.color = BLACK }
console.log('插入 10~50 后红黑树根:', root.val, '左室友:', root.left.val, '右孩子:', root.right.val)
// 输出：根 40，左室友 20(红)，右孩子 50(黑) —— 与上面手推图 100% 一致！
```

## 4. 前后端架构双视角落地

| 维度 | 为什么统治内存 | 为什么去不了硬盘（逼出下一篇 B+ 树） |
| :--- | :--- | :--- |
| **核心应用与边界** | 绝大多数插入只需改颜色，任何失衡最多 **3 次旋转** 即可修复。统治了 Linux `epoll` 网络句柄树、CFS 进程调度器、Java 8+ `HashMap` 冲突红黑树与 `TreeMap` | 硬盘每次读写固定批发 **16KB 整页**。红黑树一个节点只装 1 个数，100 万数据有 20 层高，查一次要读 20 次硬盘！为了把树压成 3 层矮胖子，逼出了 **[概念 08：B 树与 B+ 树](./08-B树与B+树.md)**！ |
