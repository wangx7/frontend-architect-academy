# 概念 06｜二叉搜索树与跷跷板旋转（BST & AVL Rotate）

> **一句话人话定义**：二叉搜索树（BST）就是把“二分查找”刻进左右两张门牌号纸条（**比我小的全挂左腿 `left`，比我大的全挂右腿 `right`**），兼顾了按顺序查找与插入不搬家；一旦按递增顺序插入歪成了单链表，就用 **“跷跷板旋转（把中间节点提上去当新老大）”** 把树扭平！

## 1. 它被什么痛点逼出来的？

在 [概念 05：哈希表](./05-哈希表与冲突拉链.md) 里我们看到，哈希表虽然单点查找只需 1 步，但取余数公式把大小顺序彻底搅乱了，遇到 **“查 100 元到 200 元之间的所有订单”** 直接傻眼。
而如果用排好序的[数组](./02-数组与连号房间.md)，虽然能二分查找也能范围查找，但每次插入新订单都要全员搬家。
怎么才能**既保持从小到大的顺序、支持二分查找，又在插入时像链表一样只改纸条不搬家**？
答案就是：**把排在正中间的数提出来当树根（老大），每个节点左手牵比自己小的、右手牵比自己大的！**

## 2. 内存门牌号从 0 到 1 慢放图

### 2.1 理想状态下的二叉搜索树（BST）
假设我们把 `40, 20, 60, 10, 30, 50, 70` 放进内存房间里：

```text
             #100 [ 40 ]
             /               (比40小走左)    (比40大走右)
          /                    #205 [ 20 ]       #308 [ 60 ]
       /     \           /         [10]     [30]     [50]     [70]
```

- **查 `30`**：从 `#100(40)` 出发 → 30 < 40 走左到 `#205(20)` → 30 > 20 走右到 `[30]`，每走一层直接砍掉一半数据（$O(\log n)$）！
- **插 `25`**：顺着 `40(左) -> 20(右) -> 30(左)` 找到空位，把 `[30].left` 的纸条指向新房间 `[25]`，所有老节点在原地纹丝不动！

### 2.2 致命死穴：按递增顺序插入 `10 -> 20 -> 30`，直接瘫倒成单向链表！
日常业务里的自增 ID 或时间戳都是递增的。如果依次插入 `10, 20, 30`：
- `10` 当根；`20` 比 `10` 大挂右边；`30` 比 `20` 大再挂右边……
整棵树彻底向右瘫倒成一条单向链表，查找速度从 $O(\log n)$ 跌回 $O(n)$！

### 2.3 核心机关慢放：怎么用“左旋”把歪树扭正，且大小顺序丝毫不乱？
看着歪成 3 层的 `10 -> 20 -> 30`，最自然的挽救办法就是：**捏住中间的 `20` 往上提当新老大，把原来的老大 `10` 拉下来当 `20` 的左孩子**（这就叫 **左旋 Left Rotate**）：

```text
【左旋前：右边太重，高 3 层】              【左旋后：对称小伞，高 2 层！】
    10                                            20
      \                                          /         20           ──(捏住 20 往上提)──►      10    30
      /  \                                           15    30                                     15  <-- 注意看 15 去哪了！
```

**最关键的细节（孩子过继原则）**：
如果 `20` 左手本来已经牵着一个孩子 `15`（注意：`15` 比 `10` 大、比 `20` 小），左旋后 `20` 的左手要改牵 `10` 了，原来的 `15` 怎么办？
因为 `10` 降级后它的右手（`10.right`）刚好空出来了，而且 `15 > 10`，所以**直接把 `15` 过继给 `10` 当右孩子**！整棵树依然严格满足“左小右大”！

### 2.4 为什么 AVL 树（严格平衡树）还没到终点？
1962 年的 **AVL 树**规定“任何节点的左右两条腿高度差绝不准超过 1，超过就立刻旋转”。但它洁癖太重了——在频繁插入删除时，往往插一个数就要从底到顶连续旋转好几次。为了减少旋转次数，科学家才发明了下一篇的 **[概念 07：2-3 树与红黑树](./07-2-3树与红黑树.md)**！

## 3. 20 行极简代码原型：亲手实现二叉树的“左旋”手术

```js
// 10 行代码看清二叉树左旋（Left Rotate）的真实指针交接
function rotateLeft(x) {
  const y = x.right       // 1. y 是右边的大儿子（即将升任新老大）
  x.right = y.left        // 2. 把 y 原来的左孩子（如 15）过继给老父亲 x 当右孩子！
  y.left = x              // 3. y 左手拉住老父亲 x，完成上位！
  return y                // 返回新的子树根 y
}

// 构造歪掉的 10 -> 20(左挂15) -> 30
const tree = {
  val: 10, left: null,
  right: { val: 20, left: { val: 15, left: null, right: null }, right: { val: 30, left: null, right: null } }
}
const balanced = rotateLeft(tree)
console.log('左旋后新根:', balanced.val, '左孩子:', balanced.left.val, '过继的孙子:', balanced.left.right.val)
// 输出：左旋后新根: 20 左孩子: 10 过继的孙子: 15
```
