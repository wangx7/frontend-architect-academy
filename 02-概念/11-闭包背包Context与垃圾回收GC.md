# 概念 11｜闭包背包 Context 与垃圾回收 GC

> **一句话人话定义**：
> - **闭包（Closure）**：就是让本该随函数结束而销毁的局部变量，**收拾行李搬进堆内存的专属小背包（`#700 Context`）里续命**，由返回出来的内层函数随身揣着 `#700` 的门牌号纸条；
> - **垃圾回收（GC）**：不是满内存找垃圾，而是**从全局根（GC Root）出发顺着门牌号纸条点名——凡是顺着纸条摸得着的房间就留着，摸不着的孤岛房间一律清空收回！**

## 1. 它们被什么痛点逼出来的？

按我们在 [概念 04：栈与队列](./04-栈与队列.md) 里学的规矩，函数一执行完 `return`，它的栈帧就会立刻弹出销毁，里面的局部变量也跟着消失。
但如果你写了一个工厂函数 `createCounter()`，把里面的小函数 `increment` 返回给了外面：小函数以后每次被调用时，还要接着读写外层函数的变量 `count`！如果 `count` 跟着栈帧一起死了，小函数去哪找它？
于是 V8 引擎发明了 **堆内存闭包背包（`Closure Context`）**。

## 2. 内存门牌号从 0 到 1 慢放图

```js
function createCounter() {
  let count = 0              // 被内层函数用到了 -> 搬进堆背包 #700！
  let temp = '用完即扔的文本' // 没人用 -> 留在栈帧里随函数结束销毁！
  return function increment() {
    return ++count
  }
}
const add = createCounter()
```

看内存格子里的真实搬家过程：

```text
【栈区 Stack】                     【堆区 Heap（顺着纸条摸得着就活着！）】
┌────────────────┐                ┌─ #800 函数对象 increment ─────────────┐
│ 全局变量 add   │ ──(纸条#800)─► │  函数代码: return ++count             │
│ [ 纸条 #800 ]  │                │  [[Scopes]] 背包纸条: #700            │
└────────────────┘                └───────────────────┬───────────────────┘
(createCounter 的栈帧                                 │ (顺着 #700 摸过去)
 及 temp 早已弹出销毁！)                              ▼
                                  ┌─ #700 闭包专属背包 (Closure Context) ─┐
                                  │  count: 0 ──► 1 ──► 2                 │
                                  └───────────────────────────────────────┘
```

### 垃圾回收（Mark-and-Sweep 标记清除）是怎么决定 `#700` 生死的？
1. **只要 `add` 还指着 `#800`**：GC 从全局变量 `add` 出发，摸到 `#800`，再顺着 `#800` 的背包纸条摸到 `#700`——标记为“活着”，绝不回收！
2. **当你执行 `add = null`（撕毁 `#800` 纸条）**：下次 GC 从根出发扫描，发现没人指向 `#800` 了，于是 `#800` 和它牵着的 `#700` 一起变成了无人问津的孤岛，**双双被回收**！（哪怕两个死对象互相指着对方——循环引用，只要从根出发摸不到它们，照样被一锅端回收！）

## 3. 20 行极简代码原型：亲眼观察闭包独立背包与内存释放

```js
function makeWallet(initMoney) {
  let balance = initMoney // 住进专属堆背包
  return {
    save: amount => (balance += amount),
    check: () => balance
  }
}

let myWallet = makeWallet(100)   // 开辟 #700 背包 (balance: 100)
let yourWallet = makeWallet(500) // 开辟 #701 背包 (balance: 500)，互不干扰！
myWallet.save(50)
console.log('我的余额:', myWallet.check(), '你的余额:', yourWallet.check()) // 150, 500

myWallet = null // 撕掉指向 #700 钱包的唯一纸条，#700 背包将在下次 GC 时自动回收
```

## 4. 前后端架构双视角落地

| 维度 | 前端架构中的体现 | 后端与系统架构中的体现 |
| :--- | :--- | :--- |
| **模块化与防抖节流** | `debounce(fn, 300)` 里的 `timer` 变量、React Hooks 闭包陷阱（旧渲染轮次的函数揣着旧背包门牌号）、Composable 状态封装 | Node.js 中间件工廠函数、Go 语言闭包捕获变量逃逸分析（Escape Analysis：编译器自动决定变量放栈还是逃逸到堆） |
| **内存泄漏排查** | 组件销毁时未移除 `window.addEventListener` 或定时器，导致全局根顺着回调函数的 `[[Scopes]]` 纸条一直拽住整个组件数据模型 | Node.js / JVM 服务端全局数组或长生命周期单例意外持有请求上下文引用导致 OOM（内存耗尽） |
