# 概念 04｜栈与队列（Stack & Queue）

> **一句话人话定义**：栈和队列并不是新的物理内存结构，而是给[数组](./02-数组与连号房间.md)或[链表](./03-单向链表与双向链表.md)立下的两条**“严禁插队的进出家规”**——**栈（Stack）是餐厅洗碗叠盘子（后放上去的盘子必须先拿走，LIFO）**，**队列（Queue）是奶茶店排队点单（先来排队的人必须先服务，FIFO）**。

## 1. 它们被什么痛点逼出来的？

数组和链表都很自由：你想读写第几个位置都可以。但在计算机管理任务时，**太自由反而会引发大乱**：
1. **函数层层调用怎么原路返回？**
   假设 `main()` 调用了 `login()`，`login()` 又调用了 `checkPassword()`。显然，必须等最里层的 `checkPassword()` 先执行完退出来，才能回到 `login()` 继续往下走，最后才退回 `main()`。如果谁先开始谁先退，程序当场错乱！这逼出了**“最后进去的人，必须最先出来”**的家规——**栈（Stack）**。
2. **异步任务与高并发请求怎么保证先来后到？**
   用户依次点击了“加入购物车”和“提交订单”，或者 1,000 个定时器回调先后到期。为了保证公平与先后顺序，必须守住**“先来排队的人，先得到处理”**的家规——**队列（Queue）**。

## 2. 内存格子逐帧慢放：看懂栈帧弹出与高性能队列的真相

### 镜头一：栈（Stack，后进先出 LIFO）——封死底部、只留顶部一个进出口的桶

栈的家规只有一条：**无论是放东西（压栈 `push`）还是拿东西（弹栈 `pop`），永远只准在桶口（栈顶 Top）操作！**
在 [概念 02：数组](./02-数组与连号房间.md) 里我们刚学过，操作数组的末尾（`arr.push()` 和 `arr.pop()`）不需要任何人搬家，天然就是 `O(1)` 极速操作。

看一段函数调用时，JS 引擎的**调用栈（Call Stack）**是怎么像叠盘子一样工作：

```js
function calcTax(price) { return price * 0.1 }
function checkout(price) { return price + calcTax(price) }
checkout(100)
```

```text
【第 1 步：调用 checkout(100) ──► 压入第 1 个栈帧盘子】
  │                       │
  ├───────────────────────┤
  │ 栈帧 1: checkout      │ ◄── 当前栈顶 (Top)：正在跑 checkout，记住局部变量 price=100
  └───────────────────────┘

【第 2 步：checkout 内部调用 calcTax(100) ──► 叠上第 2 个栈帧盘子】
  ┌───────────────────────┐
  │ 栈帧 2: calcTax       │ ◄── 当前栈顶 (Top)：正在跑 calcTax(100)
  ├───────────────────────┤
  │ 栈帧 1: checkout      │     (暂停等待上面那个盘子跑完返回结果)
  └───────────────────────┘

【第 3 步：calcTax 执行完 return 10 ──► 弹出栈顶盘子 2，自动回到盘子 1 继续算 100 + 10！】
  │ (栈帧 2 已弹出销毁！) │
  ├───────────────────────┤
  │ 栈帧 1: checkout      │ ◄── 重新变回栈顶！拿到返回值 10，算完 110 后自己也弹出销毁！
  └───────────────────────┘
```

**这就是为什么没有终止条件的死递归（`function a(){ a() }`）会报 `Maximum call stack size exceeded（爆栈）`**：因为你只往桶里叠盘子、从来不拿走，几万层之后直接把栈内存桶撑爆了！

### 镜头二：队列（Queue，先进先出 FIFO）——为什么用 `arr.shift()` 写队列是性能灾难？

队列的家规是：**新来的人永远排在队尾（入队 `enqueue`），处理完的人永远从队头离开（出队 `dequeue`）**。

```text
  队尾入队 (enqueue) ──► [ 顾客3 | 顾客2 | 顾客1 ] ──► 队头出队 (dequeue)：先服务顾客1！
```

很多前端写队列时，顺手就写 `arr.push(x)` 入队、`arr.shift()` 出队。
但请回忆 [概念 02：数组](./02-数组与连号房间.md) 的镜头二：**每次调用 `arr.shift()` 拿走排头第 `0` 号元素，数组后面剩下的所有元素都必须集体往左搬一格（`O(n)`）！**
如果队列里积压了 5 万个埋点任务，你用 `while(q.length) q.shift()` 清空队列，CPU 要白白搬家 `(50000 × 50000) / 2 ≈ 12.5 亿次`！

### 镜头三：架构师怎么写真正的 `O(1)` 极速队列？（游标移动法 / 链表法）

怎样从队头拿走元素时，后面的人不用搬家？
最简单的办法：**不删房间，只把“队头验票员 `headIdx`”往右挪一步！**

```text
【普通 arr.shift()（蠢办法：验票员死站在 #200 不动，逼后面 10 万人往前挪一步）】
  验票员固定指 #200 ──► #200[顾客2]  #201[顾客3]  #202[顾客4] ... (全员搬家 O(n)！)

【架构师游标队列（聪明办法：顾客原地坐着不动，验票员 headIdx 自己往右走一步！）】
  初始状态 (headIdx = 0) ： #200[顾客1]   #201[顾客2]   #202[顾客3]
                                ▲
                              验票员

  顾客1出队 (headIdx = 1)： #200[空置]    #201[顾客2]   #202[顾客3]
                                              ▲
                                        验票员往右走1步！(耗时 O(1)，零搬家！)
```
（定期当 `headIdx` 走过半数时，再一次性 `slice` 清理掉前面的空置房间，或者直接用 [概念 03 的链表](./03-单向链表与双向链表.md) 连接队头 `head` 和队尾 `tail`）。

## 3. 代码逐行带入走读：栈的括号/标签配对 vs 真正 `O(1)` 的游标队列

```js
// 1. 栈的黄金实战：编译器/HTML解析器如何检查嵌套括号或标签是否合法闭合？
function isValidBrackets(str) {
  const stack = []
  const pair = { ')': '(', ']': '[', '}': '{' }
  for (const ch of str) {
    if (ch === '(' || ch === '[' || ch === '{') {
      stack.push(ch) // 遇到左括号：压入栈顶等待配对
    } else {
      // 遇到右括号：必须和当前【最晚进去的栈顶左括号】配成一对！
      const top = stack.pop()
      if (top !== pair[ch]) return false
    }
  }
  return stack.length === 0 // 全部抵消完才算合法
}
// 走读 "{[]}"：依次压入 '{'、'[' ──► 遇到 ']' 弹出 '[' 匹配成功 ──► 遇到 '}' 弹出 '{' 匹配成功！
console.log('{[]} 是否合法:', isValidBrackets('{[]}')) // true
console.log('{[}] 是否合法:', isValidBrackets('{[}]')) // false

// 2. 队列的黄金实战：零搬家的 O(1) 高性能任务队列（用链表指针实现）
class FastQueue {
  constructor() {
    this.head = null // 队头门牌号（负责出队）
    this.tail = null // 队尾门牌号（负责入队）
    this.size = 0
  }
  enqueue(val) {
    const node = { val, next: null }
    if (!this.tail) {
      this.head = this.tail = node // 第 1 个人进队，既是队头也是队尾
    } else {
      this.tail.next = node        // 老队尾拿纸条拉住新人
      this.tail = node             // 更新队尾指针指向新人（O(1)）
    }
    this.size++
  }
  dequeue() {
    if (!this.head) return undefined
    const val = this.head.val
    this.head = this.head.next     // 队头指针顺着纸条往后移一步，零搬家！（O(1)）
    if (!this.head) this.tail = null
    this.size--
    return val
  }
}

const q = new FastQueue()
q.enqueue('请求A'); q.enqueue('请求B')
console.log('先出队的是:', q.dequeue(), '接着是:', q.dequeue()) // 请求A, 请求B
```

## 4. 前后端架构双视角落地

| 结构 | 前端架构中的核心应用 | 后端与系统架构中的核心应用 |
| :--- | :--- | :--- |
| **栈 (Stack，后进先出)** | 1. **Vue 3 嵌套组件副作用栈（`effectStack`）**：父组件渲染中途挂载子组件时，先把父组件的 `effect` 压栈保护，子组件渲染完弹出恢复父组件；<br>2. **富文本/画布编辑器撤销重做（Undo / Redo 双栈）**：每次操作压入 `undoStack`，点撤销时从 `undoStack` 弹出并压入 `redoStack`；<br>3. **路由历史栈（History Stack）** 与 AST 语法树深度优先遍历（DFS）。 | 1. **操作系统线程调用栈**与 JVM 虚拟机栈；<br>2. **编译器表达式求值与语法解析栈**（如 Nginx 配置解析、SQL 语法解析器）。 |
| **队列 (Queue，先进先出)** | 1. **浏览器事件循环（Event Loop）**：宏任务队列（Macrotask Queue）与微任务队列（Microtask Queue）；<br>2. **Vue 3 异步批处理更新队列（Scheduler Queue）**：同一帧内多次修改数据只入队并按组件父子顺序排队刷新；<br>3. **前端大文件分片上传并发控制池**：比如 100 个分片排进队列，只开 4 个并发通道，跑完一个从队头 `dequeue` 下一个。 | 1. **分布式消息队列（Kafka / RabbitMQ / RocketMQ）**：秒杀瞬间 10 万请求先入队削峰填谷，后端按能力从队头匀速消费；<br>2. **数据库连接池等待队列**与 Linux 内核网卡接收队列（Ring Buffer）。 |
