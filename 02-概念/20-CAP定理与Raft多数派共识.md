# 概念 20｜CAP 定理与 Raft 多数派共识

> **一句话人话定义**：
> - **CAP 定理**：当机房之间的网线被挖断（**网络分区 P**）时，两边的机器没法通气了——此时你只能二选一：要么**暂停服务拒绝写入以保住两边数据绝对一致（选 C 强一致）**，要么**允许两边先各自接客写入、等网通了再对账（选 A 高可用）**；
> - **Raft 多数派共识**：为了防止网线断了以后两边各自选出一个老大同时改数据（这叫**“脑裂”**），规定**任何选举和写入必须拿到“严格过半数（如 5 台里的至少 3 台）”签名才算数**——因为 5 台机器不管怎么断网，永远不可能同时有两个阵营都凑够 3 台！

## 1. 它们被什么痛点逼出来的？

一台数据库服务器万一硬盘烧了，全站就挂了。所以我们摆了 5 台机器存同一份数据（1 个主库 Leader + 4 个从库 Follower）。
平时主库定时给从库发心跳（“我还活着！”）。但有一天机房网线出了故障，5 台机器裂成了互相连不上的两拨：**左边 2 台（含原主库 A）**，**右边 3 台（从库 C, D, E）**。
- 右边的 C, D, E 收不到主库 A 的心跳，以为 A 死了，准备再选一个新主库；
- 左边的原主库 A 根本不知道自己被孤立了，还觉得自己是老大！
如果这时候两边都接收用户的改余额请求，一份账本就彻底裂成了两份互不相干的假账（**脑裂 Split-Brain**）！

## 2. 慢放图解：为什么“任期（Term）+ 严格过半（Quorum）”能从数学上灭绝脑裂？

```text
5 台机器集群（严格多数派门槛 = ⌊5/2⌋ + 1 = 3 票！）

       【少数派孤岛：2 台】            ⚡️ 网线断开 ⚡️           【多数派阵营：3 台】
     ┌──────────────────────┐                                ┌──────────────────────────┐
     │ 原主库 A (第1任期)   │                                │ 从库 C 发起第2任期选举！ │
     │ 从库 B               │                                │ C、D、E 三人互投凑够 3 票│
     └──────────────────────┘                                │ ──► C 当选第2任期新主库！│
      ✘ 写入请求打给 A：                                     └──────────────────────────┘
        A 最多只拿到 A、B 两票（< 3票），                     ✔ 写入请求打给 C：
        凑不够多数派，拒绝提交任何写入！                        C 拿到 C、D、E 三票（≥ 3票），
                                                                安全提交写入！

      ─────────────── ⚡️ 网络恢复后：A 看到 C 的任期(2) > 自己(1)，当场自动退位成从库！───────────────
```

记住 Raft 共识的三条保命铁律：
1. **一任期一票（Term）**：每次选举任期号加 1，每个节点在同一任期内只能投出一张赞成票（先到先得）；
2. **随机超时防平票**：每个从库等待心跳的耐心时间是随机的（比如 `150ms ~ 300ms`），最先等不及的那台先举手拉票，避免大家同一毫秒举手把票瓜分了；
3. **严格过半才提交**：无论是当选 Leader，还是确认一条数据写入成功，都必须拿到 **$\lfloor N/2 floor + 1$** 台机器的确认。这就是为什么分布式集群永远推荐部署 **奇数台（3 台或 5 台）**——因为 4 台机器需要 3 票（只允许挂 1 台），和 3 台机器需要 2 票（也只允许挂 1 台）的容错能力一模一样，买第 4 台纯属白花钱！

## 3. 25 行极简代码原型：模拟 Raft 任期压制与多数派防脑裂

```js
// 模拟 5 节点 Raft 集群在 2 vs 3 网络分区下的“少数派无法提交、多数派正常写入”
const totalNodes = 5
const quorum = Math.floor(totalNodes / 2) + 1 // 严格过半门槛：3 票

function tryCommitWrite(partitionNodes, leaderName) {
  const acks = partitionNodes.length
  if (acks >= quorum) {
    return `✅ [${leaderName}] 拿到 ${acks}/${totalNodes} 票 (≥${quorum})，写入提交成功！`
  }
  return `❌ [${leaderName}] 仅拿到 ${acks}/${totalNodes} 票 (<${quorum})，拒绝提交，成功阻止脑裂！`
}

console.log(tryCommitWrite(['A', 'B'], '少数派旧主A'))      // ❌ 仅 2 票，被拦截！
console.log(tryCommitWrite(['C', 'D', 'E'], '多数派新主C')) // ✅ 满 3 票，成功提交！
```
