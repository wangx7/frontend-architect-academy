# 概念 10｜最长递增子序列 LIS（Longest Increasing Subsequence）

> **一句话人话定义**：当一排已经显示在屏幕上的 DOM 节点顺序被打乱时，为了**少搬动真实 DOM**，我们先挑出其中**“相对先后顺序本来就没乱”的最长一串节点，让它们稳坐原地一动不动**，只花最少的力气去搬动剩下的少数几个捣乱节点——找出这串“原地不动最大队伍”的算法，就叫 **最长递增子序列（LIS）**！

## 1. 它被什么痛点逼出来的？

在浏览器里，改一个普通 JS 对象的属性只需几纳秒，但调用 `parent.insertBefore(...)` **移动一个真实 DOM 节点**却要触发浏览器的布局重算，非常昂贵。

假设页面上原本排着 4 个列表项 **`[ A, B, C, D ]`**（它们在旧列表里的位置编号分别是 **`0, 1, 2, 3`**）。
现在用户点了一下排序按钮，新列表变成了 **`[ D, A, B, C ]`**：
- 把新列表这 4 个节点换成它们在旧列表里的老位置编号，就是：**`[ 3, 0, 1, 2 ]`**。
- **笨办法（挨个搬家）**：按新列表顺序，把 `D` 搬过来、把 `A` 搬过来、把 `B` 搬过来、把 `C` 搬过来——总共移动了 **4 次真实 DOM**！
- **聪明办法（Vue 3 快速 Diff 的想法）**：
  仔细盯着 `[ 3, 0, 1, 2 ]` 这四个老位置编号看！
  你会发现后面的 **`[ 0, 1, 2 ]`（也就是 `A, B, C`）是从小到大递增的**！
  “老编号从小到大递增”意味着什么？意味着 **`A` 在 `B` 前面、`B` 在 `C` 前面这个相对先后顺序，在更新前后根本就没变过！**
  既然 `A, B, C` 三个人的前后队形本来就是对的，那我们就**让 `A, B, C` 三个真实 DOM 原地坐着一动不动**，只需要把捣乱的 `D (3)` 拎起来插到最前面——**全场只移动 1 次真实 DOM 就搞定了！**

所以，**“怎么用最少次数移动 DOM”** 这个前端工程难题，就 100% 转化成了一道纯粹的数学游戏：
> **给你一串打乱的数字（比如 `[ 2, 6, 3, 4, 1, 5 ]`），请从中挑出尽可能多的数字（可以不挨着，但不能改变它们现在的先后位置），让挑出来的数字是从小到大严格递增的！**

## 2. 从 0 到 1 逐帧慢放：Vue 3 是怎么用“潜力替补 + 前驱纸条”算出来的？

很多讲 Vue 3 源码的文章一贴出 `getSequence` 的代码，读者立刻就晕了：一会儿“贪心 + 二分替换”，一会儿又冒出一个神秘数组 `p` 倒着往回找——**为什么光靠替换还不够，非要每人发一张“前任纸条 `p`”倒着点名？**

别急，我们拿 **`arr = [ 2, 6, 3, 4, 1, 5 ]`** 这组最经典的测试数据，手把手演完下面两幕戏，你会拍案叫绝！

### 第一幕心法：潜力替补法则（同样长度的队伍，排尾的数字越小，后面越容易接上新数字！）

假设我们要组建一支递增队伍 `tails`：
1. **第 1 个来的是 `2`**：队伍里没人，直接站进 0 号位 ──► 队伍：`[ 2 ]`
2. **第 2 个来的是 `6`**：`6` 比队尾的 `2` 大，能把队伍变长！直接排在后面 ──► 队伍：`[ 2, 6 ]`
3. **第 3 个来的是 `3`**：
   - `3` 比队尾的 `6` 小，没法接在 `6` 后面把队伍变长；
   - 但是请思考：同样是排在**第 2 号位（下标 1）**的选手，**留着 `6` 划算，还是让 `3` 把 `6` 替补换下场划算？**
   - 当然是换上 **`3`** 划算！因为 `3` 比 `6` 小（更有潜力）——万一紧接着来了一个 `4`，`4` 接不在 `6` 后面，却能稳稳接在 `3` 后面！
   - 于是我们用 `3` 替补换下第一个比它大的 `6` ──► 队伍变成更有潜力的：**`[ 2, 3 ]`**！
4. **第 4 个来的是 `4`**：果然来 `4` 了！因为刚才换上了 `3`，`4 > 3`，直接接在队尾 ──► 队伍变长成：**`[ 2, 3, 4 ]`**！

---

### 第二幕惊天反转：为什么光靠“替补槽位”会篡改历史，必须配一张“前驱纸条 `p`”？

前面 4 个数字走完，队伍是 `[ 2, 3, 4 ]`，看着一切正常。
现在看第 5 个数字 **`1`** 登场时发生的惊悚一幕：
- 来了一个 **`1`**：按照“找第一个比它大的数替补上去”的规矩，`1` 比 0 号位的 `2` 还要小！于是 `1` 把 0 号位的 `2` 替补换下去了，槽位数组变成了 **`[ 1, 3, 4 ]`**！
- **⚠️ 抓包现场！** 请看看原数组 `[ 2, 6, 3, 4, 1 ]`：在原数组里，`1` 明明排在 `3` 和 `4` 的**后面**！如果这时候结束了，你直接把槽位数组 `[ 1, 3, 4 ]` 当成答案交上去，那就闹大笑话了——因为原数组里根本不存在 `1 -> 3 -> 4` 这个顺序（真实顺序是 `2 -> 3 -> 4`）！

**为什么 `1` 去替补 0 号位是合法的，却又不能让它篡改 `3` 和 `4` 的老祖宗？**
- 允许 `1` 替补 0 号位，是**为了给未来做准备**（万一后面紧跟着来 `1.2, 1.5, 1.8`，就能从 `1` 开始拉起一支 4 人新队伍）；
- 但现有的 `4` 当初进队时，它前面的正牌队友是 `3`，而 `3` 当初进队时，它前面的正牌队友是 **`2`（而不是后来篡位的 `1`）**！

怎么做到**“既允许新来的小数在槽位上替补卡位，又不忘掉每个人当年入队时的真实前任是谁”**？
Vue 3 用了我们在 [概念 01](./01-内存门牌号与指针引用.md) 和 [概念 03](./03-单向链表与双向链表.md) 最熟悉的招数——**给每个入队的数字发一张“前驱纸条 `p`”，死死记下它入队那一刻排在它左边的亲前任是谁！**

请看带了“前驱纸条”后，走完 `[ 2, 6, 3, 4, 1, 5 ]` 全程的完整连环画：

```text
原数组 arr = [ 2, 6, 3, 4, 1, 5 ]

① 来 2 ：槽位 [ 2 ]
         2 手里的前驱纸条：无 (null)

② 来 6 ：6 > 2，接在队尾 ──► 槽位 [ 2, 6 ]
         6 手里的前驱纸条：写上【我前面是 2】

③ 来 3 ：替补换下 6 ──► 槽位 [ 2, 3 ]
         3 站在了 2 后面，所以 3 手里的前驱纸条：写上【我前面是 2】

④ 来 4 ：4 > 3，接在队尾 ──► 槽位 [ 2, 3, 4 ]
         4 站在了 3 后面，所以 4 手里的前驱纸条：写上【我前面是 3】

⑤ 来 1 ：替补换下 0 号位的 2 ──► 槽位表面变成了 [ 1, 3, 4 ]
         ⚠️ 但注意：3 手里的纸条依然写着【我前面是 2】，根本没被 1 篡改！

⑥ 来 5 ：5 > 4，接在队尾 ──► 槽位变成了 [ 1, 3, 4, 5 ]（确认最长队伍总长度为 4 人！）
         5 站在了 4 后面，所以 5 手里的前驱纸条：写上【我前面是 4】

═══════════════════════════════════════════════════════════════════════════
【最后一步：顺着队尾 5 手里的前驱纸条，倒着点名还原真身！】
  从队尾最后一人【5】出发：
  - 看 5 手里的纸条 ──► 写着【4】
  - 看 4 手里的纸条 ──► 写着【3】
  - 看 3 手里的纸条 ──► 写着【2】（完美绕开了半路插队的 1！）
  倒过来排好：真实的最长递增子序列就是 【 2 ──► 3 ──► 4 ──► 5 】！
```

看到这里，你是不是浑身通透了？
- **槽位数组 `result`** 的作用：算出最长队伍**到底有几个人**，并保证每个位置上的替补选手潜力最大；
- **前驱纸条数组 `p`** 的作用：防止后来替补的小数字“篡改历史”，最后从队尾顺着纸条倒着点名，就能 100% 还原出绝对真实的历史队伍！

## 3. 代码逐行带入走读：100% 还原 Vue 3 `renderer.ts` 源码中的 `getSequence`

注意：在 Vue 3 源码里，`getSequence(arr)` 返回的不是数字本身，而是这串递增数字所在的**数组下标**（并且遇到 `0` 会直接跳过，因为在 Vue 3 里 `0` 代表本次需要新创建的全新节点，不参与老节点比对）。

```js
function getSequence(arr) {
  const p = arr.slice()       // 前驱纸条本：p[i] 记录下标 i 的元素入队时，排在它左边的真实前任下标
  const result = [0]          // 潜力槽位表：存放递增子序列的【数组下标】
  const len = arr.length

  for (let i = 0; i < len; i++) {
    const arrI = arr[i]
    if (arrI === 0) continue  // Vue3 规矩：0 代表全新节点，直接跳过

    const lastIdx = result[result.length - 1]
    // 情况 1：当前数字比槽位队尾还要大 -> 直接接在队尾，并在纸条 p[i] 上记下前任是 lastIdx！
    if (arr[lastIdx] < arrI) {
      p[i] = lastIdx
      result.push(i)
      continue
    }

    // 情况 2：当前数字较小 -> 二分查找槽位表里【第一个大于等于 arrI】的位置 u，替补上去！
    let u = 0, v = result.length - 1
    while (u < v) {
      const c = (u + v) >> 1  // 取中间位置（等价于 Math.floor((u + v) / 2)）
      if (arr[result[c]] < arrI) u = c + 1
      else v = c
    }

    if (arrI < arr[result[u]]) {
      if (u > 0) {
        p[i] = result[u - 1]  // 替补进 u 号槽位时，记下左边 (u-1) 号槽位的人当我的前任！
      }
      result[u] = i           // 完成潜力替补！
    }
  }

  // 最后一步：从槽位表最后一个下标出发，顺着前驱纸条 p 一路倒推回溯，修正被替补污染的槽位！
  let u = result.length
  let v = result[u - 1]
  while (u-- > 0) {
    result[u] = v
    v = p[v]                  // 顺着纸条找上一任
  }
  return result
}

// 用刚才手推的 [2, 6, 3, 4, 1, 5] 验证：
const sample = [2, 6, 3, 4, 1, 5]
const lisIndices = getSequence(sample)
console.log('最长递增子序列的下标:', lisIndices)                       // [0, 2, 3, 5]
console.log('对应还原出来的真实数字:', lisIndices.map(i => sample[i])) // [2, 3, 4, 5] —— 与手推完全一致！
```
