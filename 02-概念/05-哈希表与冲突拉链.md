# 概念 05｜哈希表与冲突拉链（Hash Table / Map）

> **一句话人话定义**：哈希表就是把 **[数组（按柜号 1 步直达）](./02-数组与连号房间.md)** 和 **[链表（同柜撞衫时挂纸条链）](./03-单向链表与双向链表.md)** 合体——先用一道算术公式把字符串名字（如 `"apple"`）算成数组柜号，再在撞衫的柜子里挂一条短链表，实现**按任意名字 1 步秒查（$O(1)$）**！

## 1. 它被什么痛点逼出来的？

前面我们学了[数组](./02-数组与连号房间.md)和[链表](./03-单向链表与双向链表.md)。现在你手里有 10 万个商品，你想根据商品名字 `"apple"` 查它的价格：
- 如果放进**数组** `[{ name: 'apple', price: 5 }, ...]`：因为你手里只有字符串 `"apple"`，不知道它住在第几号下标，只能用 `arr.find()` 从第 0 格翻到第 10 万格（$O(n)$）！
- 如果放进**链表**：同样得从头节点顺着纸条跑 10 万趟（$O(n)$）！

怎么才能**既按英文名字查找，又能享受到数组“1 步直达”的速度**？
唯一的办法就是：**发明一个算术公式，把英文名字 `"apple"` 当场算成一个数字房间号！**

## 2. 内存门牌号从 0 到 1 慢放图：亲手造一个 8 格储物柜

假设我们在内存里开了一个只有 **8 个格子**的数组 `buckets`（编号 `0` 号柜到 `7` 号柜）：

### 第 1 步：把字符串 `"apple"` 算成柜号（字母编码相加 + `% 8` 取余数）
我们要存 `"apple": 5`。怎么把 `"apple"` 变成 `0~7` 之间的数字？
1. **字母变数字相加**：电脑里每个字符都有固定编号（`'a'=97, 'p'=112, 'l'=108, 'e'=101`）。把 `"apple"` 五个字母加起来：
   $$97 + 112 + 112 + 108 + 101 = \mathbf{530}$$
   （这个算出来的整数 `530`，就叫 **哈希值 Hash Code**）。
2. **除以柜子总数看余数（`530 % 8`）**：我们只有 `0~7` 共 8 个柜子，没有第 530 号柜子。那就用 `530` 除以 `8` 看余数！因为**任何整数除以 8，余数永远只可能是 `0~7` 里的一个**！
   $$530 \div 8 = 66 \cdots\cdots 	ext{余 } \mathbf{2}$$
3. 直接把 `{ key: "apple", val: 5 }` 放进数组的 **`[2]` 号柜**！下次查 `"apple"` 时，再算一遍公式得出 `2`，直接打开 `[2]` 号柜拿走 `5` 元，1 步到位！

### 第 2 步：撞衫了怎么办？（哈希冲突与“拉链法”）
柜子只有 8 个，单词有千万个，肯定会有两个不同单词除以 8 余数相同！
比如现在要存另一个商品代号 `"b"`（价格 99 元）：
- 字母 `'b'` 的编号是 `98`；
- 除以 8 看余数：$98 \div 8 = 12 \cdots\cdots 	ext{余 } \mathbf{2}$！（**和 `"apple"` 算出了同一个 `[2]` 号柜！这就叫“哈希冲突”**）。

怎么让 `"apple"` 和 `"b"` 共住 `[2]` 号柜而不互相覆盖？
**在 `[2]` 号柜里挂一条我们在[概念 03](./03-单向链表与双向链表.md) 学过的单向链表（行业里叫“拉链法”）！**

```text
数组柜号 (Buckets)
  [0] ──► null
  [1] ──► null
  [2] ──► #501 { key: "apple", val: 5, next: #809 } ──► #809 { key: "b", val: 99, next: null }
  [3] ──► #610 { key: "banana", val: 3, next: null }
  ...
  [7] ──► null
```

看清楚查询 `get("b")` 的两步动作：
1. 先算公式 `98 % 8 = 2`，1 步定位到 **`[2]` 号柜**；
2. 顺着 `[2]` 号柜里那条只有两个节点的短链表核对 `key`：第一个是 `"apple"`（跳过）→ 第二个是 `"b"`（命中！返回 `99`）！

### 第 3 步：柜子快满了怎么办？（翻倍扩容 Rehash）
如果往 8 个柜子里塞 800 个商品，每个柜子后面挂 100 个人的长链表，查起来又慢了。所以当装入的元素数量超过柜子总数的 **75%（负载因子 0.75）** 时，哈希表会自动去内存申请一个 **16 格（翻倍）** 的新数组，把所有元素按 `% 16` 重新算一遍新柜号搬过去，让每个柜子后面的链表永远只有一两个节点！

## 3. 25 行极简代码原型：手写带冲突拉链的真实 `MiniMap`

```js
class MiniMap {
  constructor(size = 8) { this.buckets = new Array(size).fill(null) }
  _hash(key) {
    let sum = 0
    for (const ch of String(key)) sum += ch.charCodeAt(0)
    return sum % this.buckets.length // 取余数算出 0 ~ size-1 的柜号
  }
  set(key, val) {
    const idx = this._hash(key)
    for (let cur = this.buckets[idx]; cur; cur = cur.next) {
      if (cur.key === key) { cur.val = val; return } // 已存在则原地更新
    }
    this.buckets[idx] = { key, val, next: this.buckets[idx] } // 撞衫则挂在链表头
  }
  get(key) {
    for (let cur = this.buckets[this._hash(key)]; cur; cur = cur.next) {
      if (cur.key === key) return cur.val
    }
    return undefined
  }
}

const m = new MiniMap(8)
m.set('apple', 5); m.set('b', 99) // 530%8=2, 98%8=2，故意制造同柜撞衫！
console.log('2号柜拉链结构:', JSON.stringify(m.buckets[2]))
console.log('读取 apple:', m.get('apple'), '读取 b:', m.get('b'))
```

## 4. 前后端架构双视角落地

| 维度 | 前端架构中的体现 | 后端与系统架构中的体现 |
| :--- | :--- | :--- |
| **高频查找优化** | 把 `users.find(u => u.id === id)`（$O(n)$）重构为 `userMap.get(id)`（$O(1)$）；Vue 3 响应式依赖表中的 `depsMap`（按属性名找订阅集合） | **Redis 核心键值存储（Dict）**、Java `HashMap`、数据库内存自适应哈希索引 |
| **哈希表的唯一死穴** | **取余数打乱了大小顺序，无法做“范围查询”（如找价格 100~200 的所有商品）**——这个死穴直接逼出了下一篇的 **[二叉搜索树](./06-二叉搜索树与跷跷板旋转.md)**、**[红黑树](./07-2-3树与红黑树.md)** 与 **[B+ 树](./08-B树与B+树.md)**！ | MySQL 范围查询 `WHERE age BETWEEN 20 AND 30` 无法使用哈希索引，必须用 B+ 树索引 |
