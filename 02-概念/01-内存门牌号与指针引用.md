# 概念 01｜内存门牌号与指针引用

> **一句话人话定义**：电脑的内存条就是一长排编了门牌号（`#100`, `#101`, `#102`...）的储物格；所谓 **“指针”或“引用”**，就是格子里没直接装货物，而是装了一张写着**“货物在 `#500` 号房间”的门牌号纸条**。

## 1. 它被什么痛点逼出来的？

假设你在代码里写了一个简单的数字和一个庞大的用户对象：

```js
let age = 28
let user = { name: '张三', city: '上海', tags: ['前端', '架构'] }
```

如果把 `user` 这样大小不固定、随时可能新增属性的大块头，硬塞进管理函数调用的紧凑小格子里（栈区），每次把这个 `user` 传给另一个函数时，电脑都得把几百个字节完整复印一份——既撑爆小格子，又慢得要命！

怎么做到**“东西只存一份，全程序谁都能瞬间找到它”**？
答案是分家：
- 把庞大的 `{ name: '张三', ... }` 放进宽敞的**堆区（Heap）**大房间里（假设门牌号是 `#500`）；
- 在变量 `user` 所在的**栈区（Stack）**小格子（`#102`）里，只放一张写着 **`#500`** 的门牌号纸条！

## 2. 内存门牌号慢放图：看清“赋新值”与“改属性”的物理差别

盯着下面两段你写了无数遍的 JS 代码，看格子里到底动了哪张纸条：

```text
执行：
let a = 10;
let b = a;
b = 20;

【内存格子状态】
  #100 (变量 a) ： [ 10 ]
  #101 (变量 b) ： 先把 #100 里的 10 抄过来变成 [ 10 ]，再擦掉改成 [ 20 ]
  结果：#100 里的 a 依然是 10，毫发无损！
```

再看对象（引用类型）：

```text
执行：
let u1 = { name: '张三' }; // 对象本体住在堆房间 #500
let u2 = u1;              // 把 #102 里的门牌号纸条 "#500" 复印一份给 u2！

【内存格子状态】
  栈格子 #102 (变量 u1) ： [ 纸条 #500 ] ───┐
                                            ├──► 共同指向堆房间 #500：{ name: '张三' }
  栈格子 #103 (变量 u2) ： [ 纸条 #500 ] ───┘
```

此时请注意**两种截然不同的动作**：
- **动作 A（顺着纸条去改房间里的家具：`u2.name = '李四'`）**：电脑先读出 `u2` 里的纸条 `#500`，跑到 `#500` 房间把 `'张三'` 改成 `'李四'`。因为 `u1` 手里拿的也是 `#500` 纸条，所以 **`u1.name` 也变成了 `'李四'`**！
- **动作 B（把 `u2` 手里的纸条换成新房间的门牌号：`u2 = { name: '王五' }`）**：在堆里新开了一个 `#600` 房间住进 `'王五'`，然后把栈格子 `#103 (u2)` 里的纸条从 `#500` 擦掉改写成 `#600`。**`#102 (u1)` 手里的纸条还是 `#500`，`#500` 房间也没人动过，所以 `u1.name` 依然是原来的值！**

## 3. 15 行极简代码原型

```js
// 区分“顺着门牌号改房间内容（解引用修改）”与“换一张门牌号纸条（重新绑定）”
function mutateContent(obj) {
  obj.role = 'architect' // 顺着传进来的 #500 纸条，直接改了 #500 房间里的家具！
}

function reassignPaper(obj) {
  obj = { role: 'guest' } // 只把局部变量手里的纸条换成了 #600，外面的 #500 纹丝不动！
}

const me = { role: 'dev' } // 住在 #500
mutateContent(me)
console.log('顺着门牌号改内容后:', me.role) // 'architect'

reassignPaper(me)
console.log('局部变量换纸条后:', me.role)   // 依然是 'architect'
```
