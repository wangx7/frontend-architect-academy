# 实验 02｜亲手制造爆栈、堆 GC 与多线程竞态

> 📖 **关联教程**：[第 02 讲：变量和数据住在哪个格子里](../01-教程/第02讲-变量和数据住在哪个格子里.md) ｜ [第 03 讲：一颗 CPU 如何分身](../01-教程/第03讲-一颗CPU如何分身服务万人.md)  
> 🔍 **关联概念**：[概念 04：栈与队列](../02-概念/04-栈与队列.md) ｜ [概念 11：闭包背包与垃圾回收 GC](../02-概念/11-闭包背包Context与垃圾回收GC.md)

## 1. 实验目标

在一个脚本里亲手制造并观测三个物理现象：
1. 函数调用栈到底能叠多少层盘子就会触发 **爆栈（Stack Overflow）**；
2. 堆内存是怎么被门牌号纸条拽住不放（**内存泄漏**），撕掉纸条后又是怎么被 **GC 回收** 的；
3. 当两个真线程同时修改同一个共享内存格子时，为什么 `100000 + 100000` 算出来远小于 `200000`（**多线程竞态**）。

## 2. 复制即跑代码

新建 `lab02-memory-race.cjs`，运行 `node --expose-gc lab02-memory-race.cjs`：

```js
// lab02-memory-race.cjs —— 请使用 node --expose-gc lab02-memory-race.cjs 运行
const { Worker, isMainThread, workerData } = require('node:worker_threads')

if (isMainThread) {
  // 【实验 A】测出调用栈到底能叠几层盘子
  let depth = 0
  function recurse() { depth++; recurse() }
  try { recurse() } catch (e) {
    console.log(`1. [栈边界] 连续压入 ${depth} 个栈帧后触发爆栈保护: ${e.message}`)
  }

  // 【实验 B】亲眼看堆内存涨上去，撕掉纸条后被 GC 回收
  const mb = () => (process.memoryUsage().heapUsed / 1024 / 1024).toFixed(1) + ' MB'
  global.leakHolder = Array.from({ length: 500_000 }, (_, i) => ({ id: i }))
  console.log(`2. [堆分配] 全局纸条拽住 50 万个对象时，堆内存: ${mb()}`)
  global.leakHolder = null // 撕毁门牌号纸条！
  global.gc?.()            // 触发标记清除垃圾回收
  console.log(`3. [GC回收] 撕掉纸条并执行 GC 后，堆内存回落至: ${mb()}`)

  // 【实验 C】开启 2 个真线程，共享同一个 4 字节内存格，各加 10 万次
  const shared = new SharedArrayBuffer(4)
  let done = 0
  for (let w = 0; w < 2; w++) {
    new Worker(__filename, { workerData: shared }).on('exit', () => {
      if (++done === 2) {
        console.log(`4. [线程竞态] 2个线程各加10万次(期望200000)，实际结果:`, new Int32Array(shared)[0])
      }
    })
  }
} else {
  const arr = new Int32Array(workerData)
  for (let i = 0; i < 100_000; i++) arr[0]++ // 非原子“读-改-写”，互相吞掉对方的更新！
}
```

## 3. 破坏性对比实验：用原子操作 `Atomics.add` 治愈多线程竞态

把上面最后一行 `arr[0]++` 改成：
```js
Atomics.add(arr, 0, 1) // 硬件级原子锁：读、加、写三步不准任何人插队！
```
再次运行，你会看到结果分毫不差地变成了 **`200000`**！

## 4. 思考题

1. **在实验 B 中，如果我们忘了写 `global.leakHolder = null`，直接调 `global.gc()`，那 50 万个对象会被回收吗？为什么？**

<details>
<summary>💡 点击展开本实验思考题参考答案</summary>

绝对不会被回收！因为 GC 采用的是“从全局根（`global`）出发顺着门牌号纸条标记存活对象”的算法。只要 `global.leakHolder` 这张纸条还指着那个大数组，GC 就会认为这 50 万个对象“还有人要用（可达）”，调一百次 `gc()` 也纹丝不动。

</details>
