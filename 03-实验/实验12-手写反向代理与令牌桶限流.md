# 实验 12｜手写反向代理、健康检查与令牌桶限流

> 📖 **关联教程**：[第 15 讲：请求进机房：CDN、负载均衡、网关限流与 BFF](../01-教程/第15讲-请求进机房CDN负载均衡网关限流与BFF.md)  
> 🔍 **关联概念**：[概念 19：一致性哈希圆环与令牌桶限流](../02-概念/19-一致性哈希与令牌桶限流.md)

## 1. 实验目标

用 45 行纯 Node.js 代码，从零搭起一套真实的微型机房入口：**1 台网关反向代理（含令牌桶限流 + 轮询负载均衡 + 超时保护） + 2 台后端实例**，并亲手复现 **`200` 正常分流、`429` 限流拦截、`504` 上游超时**！

## 2. 复制即跑代码

新建 `lab12-gateway.mjs`，运行 `node lab12-gateway.mjs`：

```js
// lab12-gateway.mjs —— 45 行亲手造出 Nginx + API 网关（轮询负载均衡 + 令牌桶限流 + 504 超时）
import http from 'node:http'

// 1. 启动两台模拟后端业务服务器（Node1 正常秒回，Node2 故意在 /slow 慢 500ms）
const s1 = http.createServer((req, res) => res.end('来自后端机器 #1'))
const s2 = http.createServer((req, res) => {
  if (req.url === '/slow') setTimeout(() => res.end('慢响应'), 500)
  else res.end('来自后端机器 #2')
})
await new Promise(r => s1.listen(0, r)); await new Promise(r => s2.listen(0, r))
const upstreams = [s1.address().port, s2.address().port]
let rrIndex = 0, tokens = 3 // 令牌桶初始容量为 3 枚

// 2. 启动网关反向代理服务器
const gateway = http.createServer((req, res) => {
  if (tokens < 1) { res.writeHead(429); return res.end('429 Too Many Requests (令牌空了!)') }
  tokens--

  const targetPort = upstreams[rrIndex++ % upstreams.length] // 轮询挑选一台后端机器
  const proxyReq = http.request({ host: '127.0.0.1', port: targetPort, path: req.url, timeout: 100 }, proxyRes => {
    res.writeHead(proxyRes.statusCode)
    proxyRes.pipe(res)
  })
  proxyReq.on('timeout', () => { proxyReq.destroy(); res.writeHead(504); res.end('504 Gateway Timeout (上游太慢!)') })
  proxyReq.on('error', () => { if (!res.headersSent) { res.writeHead(502); res.end('502 Bad Gateway') } })
  req.pipe(proxyReq)
})
await new Promise(r => gateway.listen(0, r))
const gwPort = gateway.address().port

// 3. 连续发 4 次请求：前 2 次正常轮询 200，第 3 次访问 /slow 触发 504 超时，第 4 次把令牌耗尽触发 429！
for (const path of ['/api', '/api', '/slow', '/api']) {
  const r = await fetch(`http://127.0.0.1:${gwPort}${path}`)
  console.log(`请求 ${path.padEnd(5)} -> 状态码 ${r.status} | 响应: ${await r.text()}`)
}
s1.close(); s2.close(); gateway.close()
```

## 3. 破坏性实验：把后端机器 2 直接关掉制造 `502 Bad Gateway`

在发请求循环前加一行 `s2.close()`（模拟第 2 台后端服务器突然宕机进程退出，而网关还没来得及摘除它），把 `/slow` 改回 `/api` 再跑：你会亲眼看到轮到机器 2 时网关立刻返回 **`502 Bad Gateway`**！

## 4. 思考题

1. **在上面的网关中，为了不让挂掉的机器 2 导致一半的用户收到 `502`，网关应该加上哪两套检查机制？**

<details>
<summary>💡 点击展开本实验思考题参考答案</summary>

1. **主动健康检查（Active Health Check）**：网关后台起一个定时器，每隔几秒探测一次各台后端的 `/healthz` 接口，探测失败则将其从 `upstreams` 可用池中标记摘除；
2. **被动健康检查 + 幂等重试（Passive Check & Retry）**：当转发一个幂等的 `GET` 请求收到连接拒绝错误时，网关不直接向用户返回 502，而是当场将该机器暂时熔断摘除，并自动把请求换发给池子里的下一台健康机器，让用户完全无感！

</details>
