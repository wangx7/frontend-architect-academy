# 实验 10｜手写前端错误捕获、白屏与性能探针

> 📖 **关联教程**：[第 13 讲：前端性能治理、安全攻防与监控 SDK](../01-教程/第13讲-前端性能治理安全攻防与监控SDK.md)  
> 🔍 **关联概念**：[概念 15：同源策略、CORS 预检与 CSP](../02-概念/15-同源策略CORS预检与CSP.md)

## 1. 实验目标

在浏览器 Console 中亲手跑通一个 **前端可观测性探针**，实时测定当前页面的：
1. **十字采样点白屏检测结果**；
2. **首屏导航耗时拆解（DNS / TCP / TTFB / DOM 解析）**；
3. **长任务（Long Task > 50ms）自动抓拍报警**！

## 2. 复制即跑代码（浏览器 DevTools Console）

打开任意网页，按 F12 在 Console 粘贴运行以下代码：

```js
// 在浏览器 Console 直接粘贴运行：一键体检当前网页的白屏状态、网络耗时与主线程长任务！
;(function runMonitorProbe() {
  // 1. 十字采样 9 点白屏检测
  const shells = new Set(['HTML', 'BODY', '#app', '#root'])
  let emptyPoints = 0
  for (let i = 1; i <= 9; i++) {
    const el = document.elementsFromPoint((window.innerWidth * i) / 10, window.innerHeight / 2)[0]
    if (!el || shells.has(el.tagName) || shells.has('#' + el.id)) emptyPoints++
  }
  console.log(`1. [白屏探针] 9个采样点中有 ${emptyPoints} 个为空壳 -> 是否白屏:`, emptyPoints === 9)

  // 2. Navigation Timing 导航各阶段耗时拆解
  const nav = performance.getEntriesByType('navigation')[0]
  if (nav) {
    console.table({
      'DNS解析耗时': `${(nav.domainLookupEnd - nav.domainLookupStart).toFixed(1)} ms`,
      'TCP握手耗时': `${(nav.connectEnd - nav.connectStart).toFixed(1)} ms`,
      'TTFB首字节耗时': `${(nav.responseStart - nav.requestStart).toFixed(1)} ms`,
      'DOM解析耗时': `${(nav.domContentLoadedEventEnd - nav.responseEnd).toFixed(1)} ms`
    })
  }

  // 3. 开启 Long Task 探针并故意制造一个 80ms 的卡顿，看探针能否当场抓获！
  const observer = new PerformanceObserver(list => {
    for (const entry of list.getEntries()) {
      console.warn(`🚨 [长任务报警] 抓获阻塞主线程 ${entry.duration.toFixed(1)}ms 的长任务!`)
    }
  })
  observer.observe({ entryTypes: ['longtask'] })
  const end = performance.now() + 80; while (performance.now() < end) {} // 故意卡主线程 80ms
})()
```

## 3. 破坏性实验：把当前网页临时“清空变白屏”看探针反应

在控制台执行 `document.body.innerHTML = '<div id="app"></div>'` 把页面清空，然后再跑一次上面的第 1 段白屏探针代码：你会看到输出立刻变成了 **`9 个采样点中有 9 个为空壳 -> 是否白屏: true`**！

## 4. 思考题

1. **生产环境为了安全和体积，JS 代码都是压缩混淆成一行的（如 `a.b.c is not a function at index.f93b.js:1:48291`）。前端监控平台怎么在不把 `.map`（SourceMap）文件公开暴露给外网用户的前提下，把 `:1:48291` 还原成源码的真实文件名和行号？**

<details>
<summary>💡 点击展开本实验思考题参考答案</summary>

标准架构流程是：① 构建时开启 `sourcemap: 'hidden'`（生成 `.js.map` 文件，但在 `.js` 文件末尾不写入 `//# sourceMappingURL` 注释）；② 在 CI 打包流水线中，将生成的 `.js.map` 连同当前版本号上传到**内网监控平台（如 Sentry）**，紧接着在对外发布的 `dist` 目录中彻底删掉所有 `.map` 文件；③ 当线上报出压缩后的行列号 `1:48291` 时，内网监控平台根据版本号找到对应的 `.map` 文件，解析其中的 VLQ 编码即可还原出精确的 `.vue / .ts` 源码位置。

</details>
