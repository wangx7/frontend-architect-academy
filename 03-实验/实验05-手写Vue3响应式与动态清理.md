# 实验 05｜手写 Vue3 响应式与分支依赖清理

> 📖 **关联教程**：[第 07 讲：Vue 响应式、编译优化与快速 Diff](../01-教程/第07讲-Vue响应式编译优化与快速Diff.md)  
> 🔍 **关联概念**：[概念 12：WeakMap 与 Vue3 响应式依赖图](../02-概念/12-WeakMap与响应式依赖图.md)

## 1. 实验目标

用 40 行纯 JS 亲手写出一个包含 **`WeakMap -> Map -> Set` 依赖收集**、**`effectStack` 嵌套栈** 与 **动态分支旧依赖清理（`cleanup`）** 的完整迷你 Vue 3 响应式内核。

## 2. 复制即跑代码

新建 `lab05-reactivity.mjs`，运行 `node lab05-reactivity.mjs`：

```js
// lab05-reactivity.mjs —— 40 行复刻带分支自动清理的 Vue 3 响应式内核
const targetMap = new WeakMap()
let activeEffect = null
const effectStack = []

function cleanup(effectFn) {
  for (const depSet of effectFn.deps) depSet.delete(effectFn) // 从所有旧订阅集合中移除自己
  effectFn.deps.length = 0
}

function effect(fn) {
  const effectFn = () => {
    cleanup(effectFn) // 每次重新执行前，先清空上一轮收集的旧依赖！
    effectStack.push(effectFn)
    activeEffect = effectFn
    try { return fn() } finally {
      effectStack.pop()
      activeEffect = effectStack[effectStack.length - 1]
    }
  }
  effectFn.deps = []
  effectFn()
  return effectFn
}

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      if (activeEffect) {
        let depsMap = targetMap.get(target)
        if (!depsMap) targetMap.set(target, (depsMap = new Map()))
        let dep = depsMap.get(key)
        if (!dep) depsMap.set(key, (dep = new Set()))
        dep.add(activeEffect)
        activeEffect.deps.push(dep) // 反向记住自己被哪个集合收录了，方便下次 cleanup
      }
      return Reflect.get(target, key, receiver)
    },
    set(target, key, val, receiver) {
      const old = target[key]
      const res = Reflect.set(target, key, val, receiver)
      if (!Object.is(old, val)) {
        const effects = targetMap.get(target)?.get(key)
        if (effects) [...effects].forEach(f => f()) // 拷贝一份再遍历，防止边删边加死循环！
      }
      return res
    }
  })
}

const state = reactive({ showDetail: true, detailText: '机密详情' })
let runCount = 0
effect(() => {
  runCount++
  console.log(`[第 ${runCount} 次渲染] 显示:`, state.showDetail ? state.detailText : '已隐藏')
})

state.showDetail = false      // 触发第 2 次渲染（此时不再读取 detailText！）
state.detailText = '修改详情'  // 验证：因为旧依赖已被 cleanup 清理，这行修改绝对不会触发第 3 次无用渲染！
console.log('最终总渲染次数 (期望为 2):', runCount)
```

## 3. 破坏性实验：注释掉 `cleanup(effectFn)` 会发生什么？

1. 把第 12 行的 `cleanup(effectFn)` 注释掉再跑：你会看到最后一行 `state.detailText = '修改详情'` 竟然触发了 **`[第 3 次渲染] 显示: 已隐藏`**（幽灵更新）！
2. 如果你再把第 41 行的 `[...effects].forEach` 改成直接 `effects.forEach`，而保留 `cleanup(effectFn)`，程序会**直接陷入无限死循环卡死**！因为 `cleanup` 从 `Set` 里删掉了当前函数，紧接着重跑 `fn()` 又往同一个 `Set` 里重新 `add` 了该函数，JS 的 `Set.forEach` 在边删边加同一个元素时会永不停止！

## 4. 思考题

1. **为什么在 `Proxy` 的 `get/set` 里推荐使用 `Reflect.get(target, key, receiver)` 而不是直接写 `target[key]`？**

<details>
<summary>💡 点击展开本实验思考题参考答案</summary>

如果原对象里有 getter 访问器属性：`const obj = { count: 1, get double() { return this.count * 2 } }`。如果拦截器里直接写 `return target[key]`，访问 `proxy.double` 时，getter 内部的 `this` 指向的是不带响应式的原始对象 `target`，从而导致里面的 `this.count` 漏掉了依赖收集！而传入第三个参数 `Reflect.get(target, key, receiver)` 会把 `this` 正确绑定为代理对象 `proxy`，确保 `this.count` 也能被正常追踪。

</details>
