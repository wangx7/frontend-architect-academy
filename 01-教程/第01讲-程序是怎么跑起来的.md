# 第 01 讲｜程序是怎么跑起来的？

> **本讲在主线的位置**：第一卷（机器与内存底座）开篇。后面所有的浏览器渲染、Vue 更新、服务器查库，归根结底都是**某段程序在某台机器的 CPU 和内存上运行**。

## 1. 场景与核心问题

假设一个外星人指着你硬盘上的 `App.vue` 问你：**“代码我看见了，就是一段躺在硬盘上一动不动的文本。当你敲下 `npm run dev` 说它‘跑起来了’的时候，物理上到底什么东西动了？”**

很多写了几年业务的同学会答：“V8 引擎或浏览器帮我执行了。”
但浏览器和 V8 自己也是程序，它们在什么上跑？这一讲我们把外壳一层层剥到底。

## 2. 从零推导：从几十亿个开关到你的 `.vue` 组件

### 2.1 一切的尽头是开关（0 和 1）
把电脑芯片拆到不能再拆，里面只有几十亿个**晶体管开关**：通电记作 `1`，断电记作 `0`。
你写的每一行 Vue 组件、TypeScript 类型、后端接口，最终都必须翻译成这几十亿个开关的通断组合，没有任何其他魔法。

### 2.2 CPU 是个“词汇量极小、但手速极快的苦力”
CPU 根本不认识 `const`、`ref`、`console.log`，它只认识几十种极其卑微的**机器指令（0101 编码）**：
- 把内存 [`#100` 号格子](../02-概念/01-内存门牌号与指针引用.md) 里的数拿进手里的寄存器；
- 把手里的两个数加起来；
- 把结果放回内存 `#101` 号格子里。

那你写的高级语言代码是怎么变成机器指令的？全靠中间的**两段式翻译链**：

```text
你写的 App.vue (SFC 文本)
   │
   ▼  【第 1 段翻译：构建编译期（Vite / vue-compiler-sfc / tsc）】
浏览器能认的纯 JS 文本 (render 函数 + 逻辑代码)
   │
   ▼  【第 2 段翻译：运行时引擎期（V8 引擎：先生成字节码解释执行，热点代码 JIT 编译为机器码）】
CPU 唯一能看懂的 0101 机器指令
   │
   ▼  【CPU 永不停歇的三步循环】
取指 (Fetch) ──► 译码 (Decode) ──► 执行 (Execute)
```

### 2.3 示例代码：看看 `.vue` 模板在第一段翻译后变成了什么
你在 `.vue` 文件里写的 `<template>` 根本不是 HTML，而是给 Vue 编译器看的“菜谱”。编译器在打包时会把它翻译成纯 JS 的 `render` 函数：

```js
// 你写的：<template><button @click="count++">点击了 {{ count }} 次</button></template>
// 经过第一段翻译后，变成了下面这段纯 JavaScript 函数（这才是交给 V8 引擎跑的代码！）：
import { toDisplayString as _toDisplayString, createElementVNode as _createElementVNode } from 'vue'

export function render(_ctx) {
  return _createElementVNode('button', {
    onClick: () => _ctx.count++
  }, '点击了 ' + _toDisplayString(_ctx.count) + ' 次')
}
```

### 2.4 操作系统（OS）：真正的幕后大管家
当你敲下命令让程序跑起来时，其实是**操作系统（macOS / Linux / Windows）**接住了你的指令：
1. 在内存里圈出一块独立地盘（👉 见 [概念 01：内存门牌号与指针引用](../02-概念/01-内存门牌号与指针引用.md)）；
2. 把磁盘上的程序字节搬进内存格子；
3. 创建一个**进程（Process）**，并把 CPU 的时间分给它，让 CPU 开始跑“取指 → 译码 → 执行”循环。

## 3. 前后端架构双视角映射

| 你日常接触的现象 | 前端架构视角 | 后端与系统架构视角 |
| :--- | :--- | :--- |
| **翻译链分工** | Vite/Babel 把 `.vue/.ts` 翻成 `.js`（编译期），浏览器 V8 把 `.js` 翻成字节码与机器码（运行期） | `javac` 把 `.java` 翻成 `.class` 字节码，服务器 JVM 把字节码 JIT 翻成机器码；Go/Rust 直接提前翻成机器码 |
| **运行沙盒边界** | 前端 JS 活在**浏览器渲染进程沙盒**里，不能直接摸硬盘和网卡，必须通过浏览器 API 中转 | Node.js / 后端服务直接活在**操作系统进程**里，能直接读写磁盘文件、监听端口，离硬件只隔一层系统调用 |

## 5. 思考题

1. **磁盘上的 `hello.js` 是程序还是数据？当它被读进内存、CPU 开始按它的内容行动时呢？**（提示：想想 V8 的 JIT 现场把 JS 数据编译成机器指令再执行，意味着什么？）
2. **为什么电脑或服务卡死时，“重启试试”能治好 90% 的疑难杂症？** 请用“内存格子状态”解释。

<details>
<summary>💡 点击展开本讲思考题完整参考答案</summary>

1. **同一串字节，两种身份（冯·诺依曼体系的核心）**：躺在磁盘上的 `hello.js` 只是普通数据；只有当操作系统把它搬进内存、让 CPU 的程序计数器指向它并按“取指→译码→执行”对待它时，这串字节才变成了运行中的程序。因为指令和数据住在同一种内存格子里，所以程序可以“自己生成程序”——V8 的 JIT 优化、Vite 编译器、甚至 `eval` 全是靠这个原理工作的。
2. **重启 = 清空被改乱的内存格子**：程序运行的过程就是不断修改内存格子的过程。跑久了可能出现内存泄漏（借了格子没还）、状态标志位错乱或死锁。杀掉进程重启，操作系统会强制收回该进程名下的所有内存格子，重新从干净的初始代码加载，一切脏状态全部归零。

</details>
